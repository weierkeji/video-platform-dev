# 2026-10-22：视频原声、画幅与历史项目兼容

## R4：切分视频后，原声时间和增益如何一致？

1. 对象/版本：Blender 4.5 LTS 官方音频片段说明；FFmpeg 官方滤镜手册（2026-10-22 读取，本机 FFmpeg/ffprobe 9.0.2）；Web Audio 1.1 编辑草案（页面日期 2026-09-09）；Chrome 155.0.8059.82。本平台 0.2。
2. 输入/操作：阅读音频片段、GainNode、atrim、adelay、amix 和 asetpts；在本平台导入实际生成的 3 秒竖屏有声视频及无声视频。项目 24 fps、320×180；有声片段起于帧 12、源入点 12、时长 24、增益 1.5，在帧 24 用编辑器切分。源声音依次为 440/660/880 Hz，用频率变化检查源时间。
3. 实际输出：预览的 0.5 与 1.5 增益 RMS 比为 3.004374；导出的同声道 RMS 增益为 1.499667。成片 0.7 秒和 1.2 秒测得 660 Hz、875 Hz（短窗过零估计，后一源为 880 Hz）。片段前后 RMS 为 0，切分处 40 ms 窗口 RMS 为 0.132272。无音轨视频正常导出。实际生成 48 帧、2 秒 H.264/AAC MP4，项目包重导入成功。
4. 证据：[Blender 音频片段](https://docs.blender.org/manual/id/4.5/video_editing/edit/montage/strips/sound.html)、[FFmpeg 滤镜手册](https://ffmpeg.org/ffmpeg-filters.html)、[Web Audio GainNode](https://webaudio.github.io/web-audio-api/#GainNode)；[实际记录](2026-10-22-media-runtime.json)、`scripts/media-smoke.ts`、`tests/media.test.ts`、`examples/media-edit.*`。英文 Blender 页面访问受限，沿用先前已读取的官方语言版本，未运行 Blender。
5. 确认：GainNode 以乘法调节信号；FFmpeg 提供采样裁剪/延迟及关闭混音归一化的选项。实际编码曾出现极大的音轨起始时间戳；改用 `asetpts=N/SR/TB` 后，流起点、时长和真实解码 PCM 检查通过。
6. 推断与依据：用同一片段源帧映射、统一线性增益和采样边界可支撑当前剪辑语义；这是本平台独立设计，不是 Blender/LibTV 内部实现结论。单声道单位增益复制到立体声与本机 Web Audio 实测一致。
7. 未知/限制：只取第一条音轨；环绕声降混、特殊容器时间戳、变速/反放未覆盖。浏览器媒体元素按时钟纠偏，不是采样精度调度；混音可能削波，尚无限幅或响度控制。外部 AI 未参与本项。
8. 独立规格：视频/音频共用 Clip 的 start/duration/sourceIn/muted/volume；Web Audio 实现 0–2 增益，FFmpeg 按 48 kHz 边界裁切/延迟/混音；重新探测实际流、处理音频开始偏移；编码后核验流起点与时长再登记产物。取消会中止探测、浏览器和编码进程。

## R5：不同画幅与旧项目怎样保持编辑结果？

1. 对象/版本：本平台格式 v1、v2；浏览器 Canvas 2D；Chrome 155.0.8059.82。
2. 输入/操作：100×200 红色竖屏画面带蓝色顶/底条，输出 320×180；在片段属性切换 contain/cover/stretch，读取实际预览像素；恢复 contain 后切分、保存、导出并解码成片像素。迁移检查在临时 SQLite 库中放入 v1 项目、历史、版本、任务快照并重开。
3. 实际输出：contain 为黑侧边和蓝顶条，cover 为红侧边及红顶部，stretch 为红侧边和蓝顶部；实际 MP4 保留 contain 的构图。v1 数据升级为 v2，保留 stretch 和原音量；备份仍为 v1，历史恢复和任务快照可读，迁移表记录版本及备份名。
4. 证据：同一媒体运行记录及脚本；`tests/media.test.ts` 的几何矩形断言、输入不变检查、真实 SQLite 备份读取及历史恢复。
5. 确认：画幅参数经过统一命令保存、随切分保留；预览和导出读取同一 fitRect。旧项目迁移不改变已有的拉伸决定。
6. 推断与依据：显式存储适配策略比更改默认渲染行为更适合已有项目兼容；以独立数据库备份与原子快照迁移保护历史。这是自主格式设计。
7. 未知/限制：没有自由平移/缩放/旋转画面；contain 未覆盖区域暴露低轨。迁移仅覆盖 v1→v2，全量 JSON 处理不适合无限增长的项目历史；尚无备份恢复 UI。
8. 独立规格：Clip.fit 有 contain/cover/stretch，默认 contain，两个渲染入口共享居中源/目标矩形。v1 显式补 stretch；迁移前校验，完整 SQLite 备份，事务升级所有快照并写迁移记录；拒绝未知格式。

没有引入新第三方依赖或外部素材。样例画面及正弦波由 FFmpeg 生成；基础组件沿用已登记版本和许可。研究资料仅作行为依据，未复制第三方产品代码或界面。
