# 图片材质、UV 与异步渲染

日期：2026-10-23；0.7 基础支持。问题：图片如何成为共享、可编辑且可恢复的材质资源？采样通道/方向怎样与 glTF 一致？加载尚未完成、失败或切换场景时，预览和视频输出能否保持明确状态？完整 Blender/LibTV 目标不变。

## 1. 研究对象与版本

- [KHR_texture_transform](https://raw.githubusercontent.com/KhronosGroup/glTF/main/extensions/2.0/Khronos/KHR_texture_transform/README.md)：2026-10-23 读取的已批准扩展，定义 UV 的缩放、旋转、偏移及通道覆盖。
- [EXT_texture_webp](https://raw.githubusercontent.com/KhronosGroup/glTF/main/extensions/2.0/Vendor/EXT_texture_webp/README.md)：本日核对纹理 source 和 image/webp 的缓冲视图语义；没有 PNG/JPEG 后备时必须将扩展列为 required，本实现按此导出。
- Three.js 固定安装 0.180.0；[Texture 文档](https://threejs.org/docs/pages/Texture.html)与本地已安装源文件用于确认颜色空间、uv/uv1、ImageBitmap 翻转及释放语义。浏览器解码选项另核对 [createImageBitmap](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap)。文档现行页面不是锁定版本替代品，本地运行才是本版行为证据。
- REA 6.7.0 及其许可记录沿用已有基础研究。本问题主要由公开格式、真实文件、浏览器/GPU 和现有产品模块解决，没有额外安装分析引擎、运行 Blender 或访问 LibTV 私有接口。
- 本版没有新增依赖。Three.js 提供 GPU/图像采样基础，浏览器负责解码；自主层负责模型、命令、投影、格式映射、缓存生命周期和编辑界面，不把基础组件算法归为自研。

## 2. 输入与操作

`scripts/texture-fixture.ts` 原创生成四个 RGBA 色块和通道渐变 PNG、交错位置/法线/切线/UV0/UV1、五类材质贴图、摄影机和点光源。没有外部素材或 AI 生成结果。

正式入口选择含 `images/`、`geometry/` 的资源文件夹，审阅并一次导入；撤销/重做后修改边界和 30° UV 旋转，再撤销。执行 UV1 盒式投影并撤销恢复切线，尝试删除被引用图片，刷新重载。由界面导出含图片 GLB，用 Khronos 校验器读取并再导入；让原摄影机接入已有镜头，普通任务输出 12 帧 MP4，同时导出 PNG、项目包并重新打开。

开发入口的同一渲染模块检查额外延迟真实图片请求 350 ms；返回 404 检查失败；在请求和已开始解码时切换/清空场景。真实 GPU 比较贴图采样与等效材质常数，覆盖 sRGB、金属/粗糙通道、非等比缩放加 90° 旋转及 OPAQUE 忽略图片 alpha。浏览器实际编码/解码 JPEG/WebP 并核对尺寸。这些是现有产品开发检查，没有独立验证工程或模拟 AI 提供者。

## 5. 已确认事实

glTF 基础色和自发光图片的 RGB 使用 sRGB；alpha、金属 B、粗糙度 G、遮蔽 R 是线性数值。规范的 UV 原点在图片左上。Texture 的 flipY 对 ImageBitmap 无效，需在解码阶段决定；本实现不翻转、不预乘，并明确标注 GPU 颜色空间。

KHR_texture_transform 定义先缩放，再旋转，再偏移。本地 Three.js 0.180 的普通 UV 便利矩阵与该组合顺序/旋转号存在差异，因此本实现显式构建规范矩阵；已用实际 GPU 色块检查，不以 Three 加载器对变换的结果作为此次真值。这里没有宣称 Blender 原生 UI 往返或完整规范合规。

## 6. 推断与设计依据

图片 Asset 与材质绑定分离可让同一图片服务多个通道，且继续使用素材库、哈希 blob、项目包与任务快照。按绑定和颜色空间复用 GPU 纹理，避免将同一图片的 sRGB 与数据用途混在一起。这是本平台设计，并非对参考产品服务器内部的推断。

加载屏障是输出正确性的条件；出错时明确失败，不能将纯色替代画面计作成功。每次场景变化拥有独立资源生命周期与代次检查，迟到结果只能被释放。盒式投影为已有网格提供可使用图片的入口，但不能算专业自动展开。

## 7. 未知与覆盖限制

仅静态 PNG/JPEG/WebP，UV0/UV1 和基础五类 PBR；没有 UDIM、纹理绘制/烘焙、环境贴图、视频/压缩纹理、完整材质扩展、ICC/EXIF 方向工作流或专业色彩管理。PNG 动画/WebP 动画拒绝。法线贴图采用导入切线或 Three.js 导数基底，没有 MikkTSpace 生成或完整不同渲染器法线等价证据；退化 UV 和大场景性能仍待覆盖。

每图 8192 边长及 16,777,216 像素，另受 GPU 限制。场景可见非空网格引用图片文件合计 50 MB；解码像素与 GPU 纹素各限 67,108,864，图片请求 15 秒。导入界面所选文件合计 50 MB，程序解析对缓冲区和图片另各设有界限制。每次项目对象改变会重建缓存；没有增量材质更新或大素材压力证明。上传成功后事务失败可能留下无引用文件，尚无 GC。

盒式投影会覆盖通道、拆接缝；挤出侧面仍复制端点 UV。透明 BLEND 有实时排序限制，自发光不照亮其他对象。动画、蒙皮、形态键、顶点色、正交/无限远摄影机、聚光灯等交换范围尚未实现。无 Khronos 认证或完整专利审查；规范/组件权利归各自来源，原创像素按项目 MIT 提供。
